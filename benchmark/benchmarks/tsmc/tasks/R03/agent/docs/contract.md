# R03 Public API and data contract

Source events form a complete ordered prefix or suffix. Each call supplies strictly increasing positive sequences, with gaps allowed; unseen records below the checkpoint cannot be backfilled later. Replays at the same sequence have identical payloads. Each output preserves the complete JSON event. process commits in sequence order; earlier successful events may remain after a later failure. Each event's output and checkpoint must commit in the same SQLite transaction. Both fault points (after_output, after_checkpoint) occur before that event commits and must roll back the whole event. Reconnection/initialize and replay after any failure must neither lose nor duplicate outputs. `inspect` returns outputs in sequence order; initialization preserves existing state. Exceptions simulate transaction interruption, not OS kills, power loss or disk corruption; external exactly-once side effects are not guaranteed. fail_at selects the sequence and crash_point selects the stage.
