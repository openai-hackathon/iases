# R01 Public API and data contract

Persistence uses one SQLite database. `initialize(path)` is repeatable and must not clear data. `submit(path,key,payload,lose_response=False)` returns {work_order_id,machine_id,reason}. Payload contains exactly machine_id and reason, both nonempty strings; key is nonempty. The same key and payload return the same saved result without creating an order; dictionary field order is irrelevant. The same key with a different payload raises ConflictError without changing data. Different keys identify different operations, even for identical payloads. lose_response raises ConnectionError after durable commit to simulate disconnection before the response arrives; get_result or a submit retry must recover the original result. These guarantees survive reconnection and initialize, and concurrent submissions of the same key create one order. work_order_id is opaque and need not be consecutive; the fixed public CLI example starts with an empty database and returns 1. Scope is atomic writes within SQLite, excluding external equipment side effects.
